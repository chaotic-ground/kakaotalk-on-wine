패치 0001

증상

이모지가 빈 상자 두 개로 나옴

건드리는 곳

win32u

업스트림

bug 53929, 2022년부터 열려 있음

파일

0001-win32u-Draw-an-astral-character-as-one-character.patch

U+FFFF 위에 사는 것은 여기서 이모지뿐이다. 세 가지가 한꺼번에 틀려 있었고, 하나만 고쳐서는 아무것도 달라지지 않는다. 글꼴 치환과 대체와 링크 키를 오래 뒤지고도 꼼짝 않던 이유가 그것이다. 자세한 것은 패치의 커밋 메시지에 있다.

업스트림은 셋 중 첫 번째만 알고 있다.

컬러는 여전히 안 된다

글자는 나오고 색만 없다. win32u의 텍스트 경로에 컬러 글리프 지원이 아예 없다. FT_LOAD_COLOR도 CBDT도 COLR도 없고, 글리프는 현재 텍스트 색으로 칠해지는 커버리지 마스크로 DIB 드라이버에 도착한다. 자기 색을 들고 오는 글리프가 지나갈 통로가 없다.

시험

patches/emojitest.c는 글꼴에 문자를 하나 물어보고 돌아온 아웃라인의 크기를 찍는다. 창을 들여다보는 대신 숫자로 답이 나온다. 글리프가 없으면 notdef 상자라서 작고, 있으면 그렇지 않다. 

x86_64-w64-mingw32-gcc -o emojitest.exe emojitest.c -lgdi32
cp emojitest.exe <prefix>/drive_c/
wine C:\\emojitest.exe

패치 전과 후이다. 

malgun astral  U+1F33E  outline=188 bytes   box=22x26
malgun astral  U+1F33E  outline=3144 bytes  box=37x33

이모지 글꼴을 직접 고르든 폰트 링크로 닿든 같은 3144가 나와야 한다. 글리프가 그냥 존재하는 것과 링크가 동작하는 것을 그렇게 구별한다.
