From 카카오톡 on Wine

flatpak 하나와 GNOME 확장 하나면 됩니다. root도 암호도 필요 없습니다.

앱

curl -fLO https://github.com/chaotic-ground/kakaotalk-on-wine/releases/latest/download/kakaotalk.flatpak
flatpak install --user kakaotalk.flatpak

런타임은 flathub에서 오는데, 거의 모두가 이미 갖고 있는 것입니다. 없다면 리모트를 먼저 더하십시오. 

flatpak remote-add --user --if-not-exists flathub \
  https://dl.flathub.org/repo/flathub.flatpakrepo

첫 실행 때 카카오 CDN에서 설치 파일을 받아 프리픽스를 만드느라 몇 분 걸리고, 그 다음부터는 바로 뜹니다.

쓰는 것은 64비트 클라이언트입니다. 카카오가 윈도우용을 셋 배포하는데, 검색으로 흔히 나오는 app-pc.kakaocdn.net/talk/win32/는 32비트라 쓰지 않습니다.

GNOME 확장

팝업의 자리와 포커스, 트레이를 대신하는 인디케이터, 카카오톡 자신의 메뉴 열기를 맡습니다. 샌드박스 안의 앱은 ~/.local/share/gnome-shell/extensions에 아무것도 넣을 수 없기 때문에, 이것만은 손으로 깔아야 합니다. 

git clone https://github.com/chaotic-ground/kakaotalk-on-wine
cp -r kakaotalk-on-wine/gnome/kakaotalk-popup@lens0021 \
  ~/.local/share/gnome-shell/extensions/
gnome-extensions enable kakaotalk-popup@lens0021

확장을 먼저 깔아도 되는데, 아무것도 설치되어 있지 않으면 인디케이터가 flatpak 설치를 권해줍니다.

설정은 gnome/README.md에 있습니다.

문제 해결

증상이 없는 파일이 아니라 엉뚱한 Wine 오류로 나타납니다. 

wine: Call from ... to unimplemented function user32.dll.CreateDialogParamW

백신이 Wine의 PE 모듈을 격리하면 이렇게 됩니다. 한 번에 92개가 사라진 적도 있습니다. flatpak 안의 Wine은 읽기 전용이라 안전하지만, 프리픽스는 ~/.var/app 아래에 있어 그렇지 못합니다.

돌고 있는 앱에 flatpak run을 한 번 더 하지 마십시오. 앱이 죽습니다. 두 번째 클라이언트를 띄우는 이야기가 아니라, 다른 프로세스를 들여다보는 wine 프로세스면 무엇이든 그렇습니다. 인스턴스마다 PID 네임스페이스가 따로이기 때문입니다. 창을 되찾고 싶을 때는 패널 인디케이터를 쓰십시오.
